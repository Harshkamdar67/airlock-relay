WebMCP control room

Your coding agent got stuck at 2 AM. A browser agent and you fix it together.

Airlock Relay turns a blocked coding-agent session into a page that two parties operate at once. The agent reads the runtime through seven typed WebMCP tools and proposes a handoff to another model. You edit the proposal, approve it with one click, and the agent resumes the work from its checkpoint. Nothing is inferred from the DOM and nothing switches without you.

How a handoff happens

Both parties act on one shared object. The page records who did what, in order, and the agent can read that timeline back.

1The agent reads

get_session, get_events, and get_routes tell it what broke, what is on cooldown, which routes fit the context, and what spends metered usage.

Agent
2The agent proposes

prepare_handoff writes a proposal into the page. Cooldown routes, routes without room, and metered routes it was not allowed are refused with alternatives.

Agent
3You decide

Change the target, add a note, then approve or reject. Approval is bound to the exact revision you saw.

You
4The agent executes

execute_handoff resumes the session on the approved route from its checkpoint, or is refused if you edited after approving. Retries are safe.

The console

Dark-first, one accent, four actor tints. The status and the four numbers that decide the next action sit top-left; everything else is progressive disclosure.

What the agent can do

Every tool has a JSON Schema, a use-case description, and annotations. Reads carry readOnlyHint; the event log carries untrustedContentHint. Results are bounded and errors are structured so the agent can self-correct.

ToolKindWhat it does
get_sessionreadTask, active model and provider, blocked or running and why, context against the window, checkpoint.
get_eventsreadThe router's event log: requests, 429s, cooldowns, failover attempts, handoff activity.
get_routesreadEvery route with provider, tier, context window, fit, plan headroom, readiness, and metered flag.
prepare_handoffwriteCreates a proposal. Refuses cooldown routes, routes without room, and metered routes unless allowed. Never switches anything.
get_handoffreadStatus, revision, target, every change the human made, and the approval token once approved.
execute_handoffwriteResumes on the approved route. Fails before approval and when the proposal changed after approval. Idempotent.
get_replayreadThe attributed timeline: runtime, agent, and human actions in order.
